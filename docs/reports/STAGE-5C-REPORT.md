## What was built

- **Tenant isolation at the database** (`migrations/versions/0018_row_level_security.py`, `core/db.py`): every table with a `tenant_id` under `FORCE ROW LEVEL SECURITY` with four policies keyed on `app.tenant_id` (own rows: read and write) and `app.read_tenants` (read only; `public` from Stage 5D); `core.db` sets both with `set_config(…, true)` at the start of every transaction from `session.info` (`make_session_factory(engine, tenant_id, read_tenants=…)`, `set_tenant`); the scope `*` for identity resolution alone. The compose owner `tender` is a superuser and bypasses policies — found when the first test read across — so the app connects as `tender_app` (no ownership; `DATABASE_URL`) and migrations as the owner (`MIGRATION_DATABASE_URL`); the test harness connects as `tender_app` too (`TEST_APP_DATABASE_URL`) and migrates and cleans up as the owner. Every management command and the worker scope their session factory to the configured tenant.
- **Identity** (`core/models/identity.py`, migration 0017; `core/services/identity.py`: `Principal`, `IdentityService`; `core/services/oidc.py`: `OidcProvider`, `GoogleOidc` with PyJWT's `PyJWKClient` against Google's keys; `api/middleware/auth.py`, installed in place of `review_token.install`): a request is a review token, a `tie_session` cookie, a Bearer `tie_live_` key or the `X-Admin-Token` header, resolved in that order; a public request with none is refused `review_link_required` — "Sign in, or open the review link you were sent" — and the other refusals are `session_expired`, `api_key_invalid`, `login_refused`, `rate_limited` (429). `api/deps.py` gives routes a `PrincipalDep` and scopes the request session to its tenant (`set_tenant`) before the first statement. The role matrix: `reviewer` — `GET` on the tender, document, schema, review and published routes plus `POST /approvals` and `/complete-review`; `approver` — that and `POST /admin/gold`; `api_client` — the `GET` intelligence routes and, once Stage 5D adds the route, `POST /tenders/{id}/model` with the `model` scope (the policy allows the path today; the api product mounts no POST), never a write; `/admin/*` — an admin's session or the admin token. Sessions are `login_session` rows holding the hash of a random cookie token; API keys are sha256 hashes with a recognisable prefix, shown once; the rate limit per minute and the daily cap are counts over `usage_record`, written for every admitted API-key call to a versioned route (a refused one is in the request audit; the root health and files paths are not metered) and for a user's calls on the intelligence routes, attributed to the calling tenant. Routes: `GET /auth/login`, `GET /auth/callback`, `POST /auth/logout`, `GET /auth/me` (`api/v1/core/auth.py`); `GET`/`POST`/`PATCH /admin/users`, `GET`/`POST`/`DELETE /admin/api-keys`, `POST /admin/review-tokens` (minting a review link now needs an admin), `GET /admin/usage` (`api/v1/admin/identity.py`, `api/v1/schemas/identity.py`). Settings `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_ISSUER`, `OIDC_ALLOWED_DOMAINS`, `OIDC_DEFAULT_ROLE`, `BOOTSTRAP_ADMIN_EMAILS`, `SESSION_SECRET`, `SESSION_HOURS`, `API_KEY_RATE_LIMIT_PER_MIN`, `API_KEY_DAILY_CAP`. `tenant.plan` and the reserved `public` tenant seeded now for Stage 5D.
- **The published view and its state** (`tender/services/publication.py`, `published.py`, `changelog.py`, `compare.py`, `published_pdf.py`; `api/v1/tenders/published.py`, `api/v1/schemas/published.py`): `GET /tenders/{id}/published` reads values through `current_view`, which reads `canonical_fact` only — the summary and the derived sections are left out, a candidate's value appears nowhere (asserted by `tests/tender/test_published.py`) — each with its version, evidence pages, review date and the reviewer's role (from `app_user` by email, else `reviewer`); a field without a fact is a typed `not_reviewed` gap with its reason and the engine's likely page; the reliability block comes from the latest plain evaluation in `evals/results/`. `publication_state`: `published`, `update_pending` (an unreviewed later version; its `fields_touched`, the fields its runs produced reviewable candidates for, marked `possibly_superseded`), `publication_suspended` (the version touches one of the thirteen `CRITICAL_FIELDS`: bid deadline, capacity MW and MWh, EMD and PBG per MW, tariff ceiling and SCOD months in their common and `ipp` paths, minimum commissioned MW, net worth per MW, turnover and liquidity; the view answers the suspension and the amending document, no values), `not_published`. `GET /tenders/{id}/changes` (the changelog across versions), `GET /tenders/compare?ids=` (at most six tenders, a suspended one left out, provenance per cell), `GET /tenders/{id}/published.pdf` (pymupdf; the same view gives the same text, only the file identifier differs between saves; a page-reference appendix).

## Open questions

- The Google OIDC client: registered by you in the Google Cloud console with the callback `<name>/api/v1/auth/callback`; the client id and secret go into Secret Manager (cloud) and `.env` (VM).

- The host of the API product (`api.<name>`?) and whether its first keys are yours or a client's.
- On Cloud Run nothing marks a request as public: Caddy adds `X-Public-Request` on the VM, so the load balancer must add it (`--custom-request-header` on the backend, in the runbook) or every request from outside would be treated as internal and admitted. The runbook carries the step; it is the one line of the cutover that must not be skipped.
