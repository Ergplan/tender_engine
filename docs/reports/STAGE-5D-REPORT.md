## What was built

- **The library tables** (`tender/models/library.py`, migration 0019): `model_assumption`, `watchlist_entry`, `correction_case`, `publication_hold`, `oauth_client`, `oauth_code`, each under the row-level policies of 0018; the tenant of a case and of a hold is the tender's (the public library's for a library tender), written by the service in the system scope on the claimant's behalf; the tenant of an assumption, a watchlist entry, a client and a code is the caller's.
- **The one financial engine** (`tender/services/finance.py`): `power_project_finance(FixedInputs, Assumptions) -> Outputs` — project and equity IRR (`irr` by bisection), levelised cost, payback, the year-by-year cashflow; units and defaults in its docstring (capex in INR crore per MW, O&M in INR lakh per MW-year, shares and rates in percent); a CUF or a tariff the tender does not fix comes from the assumptions and `used` says which; deterministic, no model call. `tender/services/model_inputs.py` (`fixed_inputs(view)`, `PATHS`) reads the fixed parameters from the published view with the page each came from.
- **The library services** (`tender/services/library.py`, `corrections.py`; routes `api/v1/tenders/library.py`, `api/v1/admin/library.py`, the consent page `api/v1/core/oauth.py`): `normalise`, `search_tenders`, `score_match`, `find_matching_tender` (`match_threshold` 0.75; `no_match` with up to three candidates below it), `signup` (a tenant `free-<12 hex>` of plan `free` with a `reviewer`-role user; `FREE_SIGNUP_ENABLED`), `watchlist_*`, `upsert_assumptions`, `saved_assumptions`, `model_tender`, `fixed_parameters`; `open_case` (a case opens a review round scoped to the version that set the field, and changes no value), `resolve_case`, `cases`, `place_hold`/`lift_hold`, `append_takedown_row`; `publication.standing_hold`. Routes: `GET /tenders/search`, `GET /tenders/match`, `POST /tenders/{id}/model`, `PUT /tenders/{id}/assumptions`, `GET`/`POST`/`DELETE /me/watchlist`, `POST /public/corrections` (open; a `claimant_email` without login), `POST /auth/signup`; `GET /admin/corrections`, `POST /admin/corrections/{id}/resolve`, `GET`/`POST /admin/holds`, `DELETE /admin/holds/{id}`. Error `tier_required` (403) for a paid tool or route asked by a free principal. The MCP tools call these same services, so the API and the tools share one implementation.
- **The MCP server** (`mcpserver/server.py`, `tools.py`, `auth.py`; the package named `mcpserver` so as not to shadow the `mcp` SDK): `build_server` and `asgi_app` — the `MCPServer` of the `mcp` 2.3 SDK mounted at `/mcp` on the api service as stateless streamable HTTP; `UiExtension` advertises `io.modelcontextprotocol/ui` and serves the four widgets as `ui://widgets/<name>.html` resources with `text/html;profile=mcp-app`, named by the tools' `_meta.ui.resourceUri`; `ToolContext`, `ToolResult(structured, text)` and `run_tool` (the tier guard, the free limits, usage as `mcp:<tool>` on the calling tenant); `LibraryTokenVerifier` (a bearer token is an `api_key` row) and `LibraryOAuthProvider` (dynamic registration of public clients under tenant `public`, PKCE S256, the consent page at `GET`/`POST /api/v1/oauth/consent`, single-use codes of ten minutes, access tokens as `api_key` rows named `mcp:<client_id>` scoped `public:read` plus `own:read` for an enterprise plan, no refresh tokens); the SDK mounts `/authorize`, `/token`, `/register`, `/.well-known/oauth-authorization-server` and `/.well-known/oauth-protected-resource/mcp`.
- **The widgets** (`mcp/widgets/tender_card.html`, `financial_model.html`, `changes_view.html`, `comparison_table.html`, fixtures under `mcp/widgets/fixtures/`): self-contained single files, no build step, light and dark, readable at a chat column's width; the bridge as the widgets speak it — `ui/initialize` (2026-01-26) answered by `ui/notifications/initialized`, the result under `ui/notifications/tool-result` (also `ui/notifications/tool-input`, `ui/tool-result`), outgoing `tools/call` and `ui/request-tool-call` — and `window.__render(data)` for a host without it and for the tests; page chips through `get_document_page`; `not_reviewed` as marked gaps with reason and likely page; the reliability block in the footer; the financial widget's provisional figures replaced by the server's; CSV from the comparison widget's own data.

The eleven tools, as we defined them (the master prompt never did; yours to correct): `search_tenders(query?, tender_type?, agency?, state_filter?)`; `get_tender(tender)`; `get_field(tender, field_path)`; `get_document_page(document_id, page_no, quote?)`; `find_matching_tender(title_or_number, agency?, capacity_mw?)`; `list_changes(tender)`; `compare_tenders(tenders)`; `reliability_report(tender_type?)`; `model_tender(tender, model_type="power_project_finance", assumptions?)`; `save_model_assumptions(tender, assumptions, model_type=)`; `my_watchlist(add?, remove?)`. The first eight are the free tier over `public`; the last three are paid. What each returns is in `docs/ARCHITECTURE.md`, "Public library tier and MCP (Stage 5D)".

## What was skipped and why

- Refresh tokens: an access token is an `api_key` row and lives as long as a key does; a client signs in again at expiry (KNOWN-GAPS, DECISIONS).
- A second sign-up provider: free sign-up reuses the Google OIDC of Stage 5C (KNOWN-GAPS).
- The watchlist's email digest: the data is kept, nothing is sent; the enterprise product has no sending address yet (KNOWN-GAPS).
- The engine's refinements (MAT, carry-forward, working capital, salvage): the engine is one function with fixtures; refine when a model asks (KNOWN-GAPS).
- Rendering the widgets in a real MCP Apps host: the bridge follows the extension text quoted in the master prompt; a host is the check (KNOWN-GAPS).
- The matching normaliser knows the agencies and forms the corpus has (SECI, NTPC, NTPC REL, NHPC, RfS/RFP/NIT, tranche numerals); a new agency's aliases are a one-line addition.
- The widgets are hand-written single files with no build step; a shared stylesheet would come with the fifth widget, not the fourth.
