# Known gaps

Kept current every stage. Each gap says what is missing, why, and what closes it.

| Gap | Why it exists | What closes it |
| --- | --- | --- |
| Reviewers see a certificate warning once | Caddy issues the certificate from its internal CA because the app is served on a bare IP (`https://34.131.65.108`) and no public CA issues for that | Point a domain at the static IP, replace the site address in `infra/Caddyfile` with the domain and remove `tls internal`; Caddy then obtains a Let's Encrypt certificate automatically. Port 80 must be opened for the HTTP challenge, or use the TLS-ALPN challenge on 443 |
| Port 443 is open to the world | User decision on 2026-10-04: reviewers are on dynamic IPs. Since Stage 3 a request from outside reaches the API only with a valid review token, and then only the review routes of that token's tender (`api/middleware/review_token.py`); stored files are served after the same check. A token in a URL can leak (forwarded message, browser history); it expires after 30 days and is replaced by creating a new one | The Stage 4 `/admin/reliability` dashboard needs its own guard (an admin token is the smallest change); decide before Stage 4. Login and roles are Stage 5 |
| No sample tender of type `ipp` | The 13-tender set covers fdre, bess, solar, wind, hybrid, transmission, generation and epc | `tender/domain_packs/power/ipp.yaml` will be seeded from the field catalogue only and flagged untested until an IPP document is added to `/work/tenders/ipp/` |
| Three tenders are incomplete | NTPC REL Anantapur WTG and NTPC PHES are NIT-only (full documents behind the NTPC e-tender login); Ramagiri Amendment-01 was not in the link set | Add the missing files to the tender folders and update `manifest.yaml` |
| VM is small on CPU and memory: 2 vCPU, 3.9 GB RAM | The user decided on 2026-10-04 to resize to e2-standard-4. The build agent runs on the VM and cannot stop it; the resize is the user's step (commands in the Stage 2 report). Until then the watcher must be stopped during heavy parsing | `gcloud compute instances stop`, `set-machine-type e2-standard-4`, `start`, then `make up`; the static IP stays attached |
| `make report` does not exist yet | The reliability report is Stage 4 | Added in Stage 4 |
| GCP mutations cannot be run by the build agent | The Claude Code permission classifier blocks firewall and address changes from the agent session | The user runs `infra/firewall.sh` with the `!` prefix; the agent verifies read-only |
| `make check` and `make test` need the `web_node_modules` volume | The tests container runs tsc and vitest from a volume that the web image populates | Run `make up` (or `make deploy`) once before them on a fresh machine; `make deploy` refreshes the volume with `npm ci` |
| Containers run in development mode | `uvicorn --reload` and the Vite dev server are used in phase 1 so the build agent's edits are live | Stage 5C builds production images (static web bundle, no reload) for Cloud Run |
| Postgres password is the compose default `tender` | The database listens only on the compose network and on 127.0.0.1 of the VM | Move to a generated secret in `.env` when Cloud SQL arrives in Stage 5C |
| Bid dates of nine tenders come from a snapshot of the agency's tender web page | Their RfS says "as per NIT"; SECI and NTPC publish the notice as a web page, not a PDF. `scripts/fetch_notices.py` writes the page's own label and value pairs into a small PDF (`Tender_notice_page_<slug>.pdf`, role `nit`, with the URL and the retrieval date, 2026-10-04; the HTML is kept beside it) attached to the tender's latest version. The page shows the dates as they stood that day, after every extension; it does not say which amendment set them | A reviewer checks the date against the URL printed in the document. Fetch again if a tender is extended; a new snapshot is a new document |
| A quote read across a wrapped table cell is located by its words, not its exact character sequence | The text layer of a table interleaves a wrapped cell label with the value ("Closing 12.04.2024 / Date & Time"), while the model quotes it in reading order. First seen on NHPC FDRE-II page 22 (bid deadline), where the exact and fuzzy matchers both failed | Handled in `core.services.evidence._locate_reordered`: consecutive page words matched in any order at the same threshold, every number in the quote required unchanged. The highlight box then covers the whole run of words, which can include a neighbouring cell |
| `git push` over SSH does not work from a new session | The VM's SSH key is passphrase-protected and was unlocked only in the first session's agent | Pushes go over HTTPS with the `gh` login (`gh auth git-credential`). Run `gh auth setup-git` and switch the remote to HTTPS, or add the key to an agent, to make plain `git push` work again |
| A field whose only candidates are `rejected` (value without a quote) shows no candidate and cannot be decided | There is no candidate to attach the decision to. The card says nothing was extracted; such a field does not hold back Complete review | Re-run extraction. If it occurs in reviews, add a reviewer-created entry |
| Repeating an identical approval after a re-extraction answers 422, not 200 | The candidate is superseded by then and superseded candidates cannot be decided | Acceptable in phase 1 (one reviewer per tender); revisit with the Stage 3 UI |
| Page selection drops pages beyond 80 per field group and falls back to keyword pages, then the first 40 pages | `extract_max_pages_per_group = 80` bounds cost per group; when no section matches the routing hints, pages mentioning the keywords are used, and failing that the opening pages | Stage 2 answer rates per section are in EXTRACTION-SUMMARY.md (49% for key dates and 48% for eligibility, mostly fields the documents state per MW, in months, or defer to the NIT). Whether a value sat on a dropped page is only known after review (Stage 4) |
| A page position outside the attached range is stored as the first page of the window when the quote is not located | The model returned a printed page number instead of the attached position and the quote was found nowhere in the window | The span is marked `unresolved` and the candidate goes to review; the stated page shown may be unrelated |
| The `canonical_fact` guard is a trigger, not a privilege | Trigger `canonical_fact_guard` (migration 0004) refuses an insert without a live approval of the same field, any change other than retiring a superseded fact, and any delete. The application connects as the table owner, which could still disable the trigger or `TRUNCATE` the table (the test fixture uses `TRUNCATE` between tests) | Stage 5C: a dedicated database role for the application without owner rights |
| A value that sits only on a scanned page cannot be approved or supplied | No canonical value exists without located evidence, and a quote can only be located in a text layer. The reviewer fills an empty field in the edit form with the page and the words (typed, or taken from a selection in the PDF); a page without a text layer has nothing to select or locate | Add a reviewer evidence kind that is a region of the page image, when a scanned tender occurs. None of the 13 tenders needs it |
| A reviewer's evidence must be in the document the candidate was read from | `ApprovalService` locates the reviewer's quote in the run's document | The edit form says so. If reviews need evidence from another document of the version, let the request name the document |
| Evidence without a box cannot be highlighted on its line | The screen draws the stored box. A span with character offsets but no box would outline its whole page, as an unlocated quote does. No located span in the database lacks a box (3,592 of 3,592) | Compute the line's box from the page's character boxes in the review state if such a span ever occurs |
| Load times depend on what else the VM is doing | Two cores: with the test watcher running the full suite, a real tender took up to 4.8 s to first paint and 6.2 s to its first PDF page; on a quiet VM 1.0 s and 1.3 s | Resize the VM (the user's step), or stop the watcher while reviewers work. The timing bar is checked by `web/e2e/real-load.spec.ts` against the deployed app |
| A review cannot be completed with a field left flagged | The summary is required and can only be decided once every other field with a candidate has a decision, so a flag must be resolved (approved, edited or marked not in document) before Complete review | By design since 2026-10-05 (DECISIONS.md). If reviewers need to hand over a tender with open questions, let a flag with a note count for the summary's lock and say so in the snapshot |
| If the summary cannot be written again, the review cannot be completed by approval | After a correction the summary must be rewritten before it can be approved; if the model call fails (no credit, an outage) the card keeps saying the summary will be written again | The reviewer can edit the summary by hand, which is allowed once the other fields are decided; or `python -m scripts.ingest_tenders summarize --only <slug>` once the model is reachable |
| The summary leaves out fields without located evidence | A sentence inherits the evidence of its field; a value whose quote was not located has none to give. Two values of SECI FDRE-RTC-V are in that state | They are flagged for review as fields; once a reviewer supplies the evidence the summary can be asked for again |
| Narrative sentences still come from a 40-page reading | What is procured, buyer and offtaker, and location are taken from the page-read summary where no field holds them | Add fields for them if reviews show these sentences wrong |
| A sentence of the summary can end in many numbers | A sentence inherits every located quote of every field it draws on; a field with four quotes brings four numbers. The NHPC FDRE-II summary has 128 passages | The chips of such a summary are behind a toggle and the numbers in the text open the passages. If reviewers find it heavy, inherit one quote per field |
| The model may cite a field for a sentence that says something else | The code guarantees that every number has the evidence of a real field; it cannot check that the sentence says what the field says | This is what the reviewer checks on the summary card: the number opens the field's passage. Stage 4 measures how often the summary is edited |
| Page thumbnails are the full page images scaled down | No separate thumbnails are rendered at parse time | Loaded lazily and only when the strip is open; render small images at parse if the strip proves slow |
| The reviewer screen is served by the Vite dev server | Phase 1 containers run in development mode | Stage 5C builds a static bundle. Measured on the VM: first paint 1.4 s, first PDF page 1.7 s on the largest tender |
| One worker per tenant | The worker claims only jobs of the tenant in its `TENANT_ID` | Phase 1 has one tenant. Stage 5C: one worker per tenant or a tenant loop |

| Real-model cost | Stage 1: about USD 22. Stage 2: about USD 205 for the first full extraction (USD 190.65 of runs, USD 12.66 of section maps, USD 1.79 for the end-to-end test), then USD 32.92 after acceptance (11 amendment maps, the nine notices, and key dates and eligibility read again under the changed schema). Per tender on the full schema: USD 10 to 15 for a single RfS, USD 20 to 30 with agreements, amendments or two EPC volumes. Native PDF pages cost about 2,800 tokens each and are re-sent for every section. Running total: about USD 260 | Stage 3 adds prompt caching for shared page windows and the batch API for runs nobody waits for, and reports the effect (master prompt, Stage 3). Every stage report prints the stage cost and the running total |
| Amendment routing is not proven | A missed corrigendum is the most expensive error here. Every amending document is now read for the union of two answers: the sections whose keywords occur in it, and the sections a full map of the document (one model call, `amendment_map/v1`) assigns its changes to. Each comparison is in the audit log (`amendment_routing`; `python -m scripts.ingest_tenders routing-report`). On the 11 amending documents of the set the two disagreed on 9: the map found a section the keywords missed on 7 (one real change, the technical qualification in Ramagiri Amendment-03; the rest restatements), and the keywords selected a section the map did not on 7. Neither method alone is trusted, and a change both miss is still possible | Stage 3 and 4 reviews of the amended tenders: every change a reviewer finds that neither method routed is a defect to fix here. Proven when reviewers have checked the amended tenders without finding one |
| A reviewer cannot record that an amendment removes a value | In the current view a later version replaces an earlier fact only when it states a value; "not in document" on an amendment leaves the original in place | Add an explicit "withdrawn by this version" decision if a real amendment needs it |
| Cross-field rules do not compare values that come from different documents of one version | Validation runs per extraction run, and a run reads one document | Only matters when a rule's fields are extracted from different documents; today every rule's fields sit in one section. Move such a rule to a run rule that reads the version's live candidates if it arises |
| PSA documents are stored but not read | No catalogue field is a term of the power sale agreement | Add fields to the pack and `psa` to the roles of the section that reads them |
| Several workers must be started together | `jobs.requeue_orphans` runs when a worker starts and re-queues every job marked `running`, which is right for one worker and wrong while another worker is mid-job | Stage 5C: a lease per job (worker id and heartbeat). Until then scale the worker only while the queue is idle |
| `tender.status` is refreshed when a tender is read | There is no hook when the last run of a tender validates; `TenderService.refresh_status` runs on `GET /tenders`, `GET /tenders/{id}` and in the management command. `reviewed` is set when a review is completed | A worker hook can replace the lazy refresh |
| A quote that skips words of a passage is located as if it were verbatim | The fourth evidence matcher accepts the quote's words in order with other words between them (needed for two-column amendment tables); it cannot tell a neighbouring column from words the model left out | Every number in the quote must be on the page, and the reviewer sees the highlighted words. If reviews show wrong highlights, restrict the matcher to pages where character boxes show two text columns |
| Two sections per document are read in two 40-page calls and can return two candidates for one field | A window above 40 pages is split; each half answers on its own, and a half that sees only part of a clause says so at low confidence | The best candidate is shown and the others are counted as alternatives. Stage 4 shows whether the split costs accuracy |
| The evidence resolver fails 2 of 220 corpus cases | `real-0080`: a watermark printed through a heading breaks a word in the text layer. `real-0142`: a wrapped table cell read out of order in a quote without a number; words alone are never matched out of order | Listed in `tests/core/evidence_corpus/known_failures.json`; the corpus test fails if any other case fails. Fix when a pattern recurs in reviews |
| Candidates extracted before the resolver changed keep their old evidence | Candidates and evidence spans are immutable. Sections that were not read again after 2026-10-04 (everything but key dates and eligibility) carry spans located by the earlier resolver; two values of SECI FDRE-RTC-V Amendment-01 are still unlocated although the present resolver finds their quote | They show as `needs_review`; the reviewer supplies the page and quote, or the section is extracted again |
| Schema and prompts changed under version `v1` | Before the first review the schema gained basis fields, lost two EPC fields and renamed bid validity, and two prompts were edited, all still called `v1`; the affected sections were extracted again, so no live candidate comes from the earlier text | From the `stage-3-start` tag the `v1` schemas and prompts are frozen: a later change is a new version (DECISIONS.md) |
| A batch can be paid for twice in one narrow case | `LLMClient.submit_batch` hands the batch to the provider and then saves its row; a crash between the two leaves a batch nobody collects, and the run submits it again | Save the batch row before submitting, with the provider id filled in afterwards. Not done: a batch of one run costs a few dollars and the worker is a single process |
| Whether the calls of a batch's second wave read the cache is up to the provider | Cache reads inside a batch are best effort; the window is kept for one hour between the waves | The share of cached tokens of every batch run is in `extraction_run.token_cached`; the Stage 3 report gives the measured rate. A miss costs the half-price input, never more than Stage 2 |
| A group in a shared window reads pages it did not ask for | The shared window is the union of its groups' windows (at most 80 pages) | Measured on two tenders in the Stage 3 report (evidence-location rate and answer rate before and after); Stage 4 accuracy per field is the real test. `EXTRACT_SHARE_WINDOWS=false` switches sharing off |
| A run queued by the amendment map is not in the response of `POST /tenders/{id}/extract` | The map is a background job; it queues the run when it has finished | The UI polls `GET /tenders/{id}/review-state`, whose `runs` list shows it |
| The check of numbers against quotes compares numbers, not meaning | `structured_numbers_quoted` passes when the number is printed anywhere in the field's quotes ("10 Crores" also satisfies a 10); it fails for a number the document implies without printing (100 for "at the full tariff"), for unit conversions other than lakh, crore and paise, and for a schedule whose years are not all inside the quotes | Such a value is `needs_review`, never dropped; the reviewer decides. Counts are in the stage report |
| No accuracy by key for structured fields yet | A reviewer's edit of a record is recorded as one correction of the field, whichever key changed | Compute per key from the candidate's record and the final record when the gold-set metrics are built (Stage 4) |
| A list of records is edited as text lines | `shortfall_rules`, milestone payments and element-wise COD are edited as `key: value | key: value` lines, not key by key | Give lists the same per-key form as records if reviewers edit them often |
| The model input profile is designed, not built | `GET /tenders/{id}/model-inputs` and `model_assumption` do not exist | Built with the financial model stage |

| `revalidate` checks only runs of the current schema version | Runs made under `v1` and read under `v2` keep the validation results they got when they were made; a rule added later is not applied to them | Extend `revalidate` to every version in `versions_read_as` when a rule is added that concerns a field of a section not read again |
| Feedback of a cleared decision is still in the feedback table | Clearing a decision supersedes it but keeps its feedback row as history (nothing is deleted) | The Stage 4 feedback report must count only feedback whose approval is active; until then a cleared edit counts as a correction in a raw query of the table |
| The version check compares definitions, not meaning | `verify_versions` fails the load for a removed field or a changed type, unit, set of allowed values or record keys. A field whose definition stays the same while its help text gives it another meaning passes | Treat a change of meaning as a change of field: give it a new path, or list it under `read_again` and read its section again |
| An edit that changes only a field's evidence does not reach the summary | The summary is written again when the record's values change; its input holds values, not passages. A reviewer who keeps a value and gives a better passage for it leaves the summary pointing at the model's passage for that field | Include the passages' identity in what decides a rewrite, or let the summary take the reviewer's evidence without a rewrite; neither changes a stated value |
| GST is not a field of its own | Fees and charges are extracted as printed, with the GST wording in the prose; a financial model needs the whole amount and the rate separately (owner's review, 2026-10-06) | Schema `v3`: a GST rate and an inclusive/exclusive flag beside every fee or charge |
| Worked examples in annexures are not captured | A penalty rule is extracted as a rule; the illustrative example the tender gives (NHPC Annexure-1A) is what a bidder uses and is not captured or linked (owner's review) | Schema `v3`: a structured example (inputs, result) or a page link beside the rule |
| An approved value cannot carry a note | Four of the owner's edits in the first real review kept the value and added a remark; the only way to attach one is Edit, which the feedback table does not count as a correction | Let "approved" take a note, and show it on the card |
| Single-valued fields that tenders answer with several values | `emd_form` holds one instrument; NHPC accepts four | Schema `v3`: a list for such fields, found by the gold set |
| One gold record (NHPC FDRE-II); the accuracy figures rest on one tender and the stability bar is not met | Stage 4 ends with the dashboard and the report built; the reviews of the other twelve tenders are the owner's work in the review phase | `make gold` after each confirmed review; the bar needs two reviewed tenders for epc, fdre and wind |
| Long-text fields (18 of 97 on NHPC FDRE-II) are not scored | No rule tells a right summary from a wrong one; the master prompt leaves them to human judgement | A rubric or a second-model judgement in Stage 5, if wanted |
| The prompt comparison in the report rests on `evals/results/`, one file per evaluation; the bar's "last two prompt versions" are the last two versions of each section prompt that scored candidates carry, so with one version per section the condition holds trivially | No prompt has been promoted since gold records exist | The first promotion, measured with `make eval PROMPT=`, with its before and after in DECISIONS.md |
| Reviewer time is counted between decisions in sittings of under fifteen minutes' gap, from the approval rows | The screen does not report time on page | Time on page from the browser, if a truer figure is wanted |
