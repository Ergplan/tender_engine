## Domain guidance: Firm and dispatchable RE terms: demand or supply profile, peak window, availability, firmness, shortfall penalty, storage, excess energy.

Indian renewable-energy tenders, common ground for every section:

- Agencies name the same thing differently. SECI: RfS, Bid Information Sheet, SCSD or SCD, Buying Entity, Success Charges. NTPC and NTPC REL: IFB, NIT, Bid Data Sheet, Employer, Bid Security. NHPC: NIT, Critical Date Sheet, SCC. SJVN and state agencies: RfS or RfP, Scheduled Commissioning Date. EPC tenders speak of Employer, Contractor, Contract Performance Security.
- Amounts are often written in the Indian system: 1 lakh = 100,000; 1 crore = 10,000,000; "Rs. 9,28,000" is 928000. Give plain rupees and say in the rationale what the document printed.
- "As per NIT", "as per the portal" or "to be notified" is not a value. Return null and say which document will set it.
- If the attached document is an amendment, corrigendum or clarification, it overrides the base tender. Give a value only where this document states the new value, quote the amended text, and return null for everything it does not change.

- `demand_profile`: describe the supply obligation as written (for example 4 hours of assured peak supply per day at rated capacity, or a round-the-clock profile with a minimum annual availability).
- `assured_availability_percent`: the availability or Demand Fulfilment Ratio the developer must meet; say in the rationale whether it is monthly or annual.
- `shortfall_compensation_multiple`: the multiple of the tariff charged per unit of shortfall (1.5 for "1.5 times the PPA tariff").
- `storage_mandatory` is true only when the pages require an energy storage system; an optional ESS is false.

Structured fields (`*_structured`, `shortfall_rules`, `cuf_terms`) hold the numbers of the prose field beside them, for a financial model:

- Give a key only when these pages state it. A key the pages do not state is left out; never write 0, never compute a number the document does not print, never fill a key from what is usual in such tenders.
- Give each number as the document prints it, converted only to the key's unit (lakh and crore to rupees, paise to rupees), so that the number can be found in your quotes.
- Quote the passages that state the numbers. A structured value with no quote for a number will be sent back.
- When the pages state none of the keys, the value is null.
- The prose field and the structured field must say the same thing.

- `demand_profile_structured`: `basis` availability_pct when the obligation is an availability during peak hours, energy_per_mw_per_day when it is an energy per MW per day in peak hours. `peak_blocks`: one item per window ("2 hours in the morning within 05:00-10:00" is window_start=05:00; window_end=10:00; hours=2); when the window is defined without clock times (non-solar hours, hours chosen later) give no blocks and say who chooses in `peak_hours_chosen_by`. CUF band limits as a percentage of the declared CUF. `peak_availability_pct` must equal `assured_availability_percent` when that is the peak availability.
- `excess_energy_structured`: `fixed_inr_per_kwh` must equal `excess_energy_price_inr_per_kwh` when both are given.
